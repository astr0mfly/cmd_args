# 子目录原生文档（Markdown 代码地图）

> 核心：md 与 `.h`/`.cpp` 同目录、同地位、同评审。文档是代码地图的一部分，不是 README 的副本，也不是集中式 wiki。

## 一、原则（先记住这 6 条）

1. **md 与源码同地位**：文档放在被描述目录内，随该目录代码一起提交与评审；不再维护集中式"代码地图"文档。
2. **一目录一篇**：文档名 = 目录名 + `.md`（`context/context.md`、`example/once/once.md`）。
3. **禁用 `AGENT.md`**：历史文件名，已废弃；新建/迁移一律用目录名。
4. **源码是唯一事实源**：文档中的每条事实都必须能从源码/构建文件直接验证；旧文档事实先核对再沿用。
5. **文档可定位**：索引覆盖目录内全部源码与构建文件；相对链接可点击；符号名可用 grep 命中。
6. **不编造**：不写不存在的文件、符号、默认值；不确定就写"未验证"或不写。

## 二、命名与位置

| 目录 | 文档 |
| --- | --- |
| `include/cmd_args/` | `include/cmd_args/cmd_args.md` |
| `include/cmd_args/context/` | `include/cmd_args/context/context.md` |
| `example/once/` | `example/once/once.md` |
| `dfx/unit_test/` | `dfx/unit_test/unit_test.md` |
| `extern/magic_enum/` | `extern/magic_enum/magic_enum.md` |

- 每个覆盖根目录还有一篇同名导航文档（如 `include/cmd_args/cmd_args.md`），只做目录表与解析管线，不复制细节。
- vendored 目录同样一篇：索引登记全部头文件（相对文档目录的路径），并注明版本、许可证、引用点。
- 新增子目录 → 同时新增同名文档；删除/改名 → 同步父文档与项目登记表。
- 一个目录只有一篇官方文档；不放 `index.md`/`notes.md` 等第二份说明（确有外部资料时在正文注明）。

## 三、模板（逐字遵守）

```markdown
# <目录名> — <一句话定位>

> **摘要**：<2–4 句：本目录在项目中的角色、解决什么问题、对外可见能力、边界。>
> **联系**：<上级文档 / 子目录文档 / 依赖头文件 / 使用方（示例、单测）/ README 章节；一律相对链接。>

## truth

<可从源码直接验证的硬事实：文件→类型/职责、关键签名、数据流与状态机、错误码、常量与阈值、构建 target。>

## 约束

<违反即错误的硬规则：语言/标准、header-only、命名空间宏、命名规范、依赖边界、vendored 不改、时序约束。>

## 索引

| 文件 | 关键符号 | 职责 |
| --- | --- | --- |
| `xxx.h` | `Class` / `func` | … |

## 决策

- <决策>：<理由 + 代价>；<被否方案>。

## 教训

- <现象>：<根因 + 规避方式 + 依据文件:行>。
```

硬性要求：

- H1 必须以目录名开头；H1 下紧跟两行 blockquote（**摘要**、**联系**）。
- 五个 H2 顺序固定：truth → 约束 → 索引 → 决策 → 教训；不新增第六节。
- UTF-8 无 BOM，LF 换行；中文正文，标识符/签名保留英文原样。

## 四、逐节写法

### 摘要
- 2–4 句，回答"这个目录是什么、凭什么存在"。
- 必须包含：角色（如"解析前的参数登记层"）、核心抽象（类/接口名）、对外能力、边界（不做什么）。

### 联系
- 至少三类：上级文档链接、子目录文档、依赖头文件/使用方。
- 依赖写相对路径；使用方写 example target 或 `test_*.cpp`；README 只引确有对应章节的锚点。
- 跨目录概念只在一处详述，其余写"联系 + 一句话"。

### truth
- 文件表：文件 → 主要类型/职责（行数可写，标注核对日期）。
- 公共签名用反引号原样抄写，禁止凭印象简化。
- 数据流/状态机用有序列表或 mermaid（≤15 节点）。
- 错误码、枚举值、常量、默认值、构建 target、依赖开关逐条列。
- 每条事实尽量带依据：`path/to/file.h:120`；行号只用于稳定锚点并注明核对日期（如"2026-10-25 核对"）。

### 约束
- 写成"必须/禁止"，可核对：header-only、C++20、双平台、命名空间宏、命名规范、target `set_default(false)`、vendored 不修改、动作时序。
- 每条约束给出违反后果或依据文件。

### 索引
- 表格：文件 | 关键符号 | 职责；按路径排序。
- 必须覆盖目录内**全部非 md 文件**（含 `xmake.lua`、`main.cpp`、fixture/脚本），子目录单独一行或在行内注明。
- 符号名与源码一致（grep 可命中）；一个文件多个符号用 `/` 分隔。

### 决策
- 只记"为什么这样设计"：选项、理由、代价、被否方案、迁移历史（旧路径与日期）。
- 一条决策一条 bullet，不写流水账。

### 教训
- 只写真实发生过的坑：现象 → 根因 → 规避 → 依据（`文件:行`）。
- 优先写文档漂移（旧文档写错/过期）、已知缺陷、未接线代码、易错 API。

## 五、工作流（0–7）

0. **定范围**：用 glob/目录树列出目标目录，确认覆盖清单（根目录 + 每个含源码子目录；含 vendored）。
1. **读源码**：逐文件读头/实现，记录类型、签名、常量、错误码、构建配置。
2. **抽事实**：所有数字（文件数、用例数、行数、错误码）现场统计或 grep，禁止沿用旧文档数字。
3. **写头部**：先写摘要与联系，确保读者不读代码就知道"这是什么、从哪来、谁在用"。
4. **写五节**：按模板填 truth → 约束 → 索引 → 决策 → 教训。
5. **校验**：`node .dsh/skills/dsi-native-docs/scripts/check-docs.mjs <目录列表>`；退出码 0 才算通过。
6. **更新地图**：同步父目录文档的索引/联系、项目登记表（如 `.dsh/Agent.md` §12 覆盖清单与源码地图）。
7. **汇报**：列出新增/修改文件、覆盖目录数、校验结果、已知偏差；未要求不跑构建、不 commit。

## 六、校验脚本

```bash
node .dsh/skills/dsi-native-docs/scripts/check-docs.mjs include/cmd_args example dfx/unit_test
```

- 在仓库根目录执行；递归扫描显式传入的目录，跳过隐藏目录与 `build`/`node_modules`/`.xmake`。
- 对每个含源码文件（`.h`/`.hpp`/`.cpp`/`.cc`/`.c`/`.lua`/`.py`/`.js`/`.ts` 等）的目录，以及含源码子目录的分组目录（如 `extern/`），要求 `<目录名>.md`；已存在的同名文档也会被校验。
- 检查项：无 BOM；H1 含目录名；两行 blockquote 且含摘要/联系；五节齐全且顺序正确；相对链接可解析；索引覆盖目录内全部非 md 文件；子目录名在正文出现。
- 失败逐条打印 `FAIL <文档>: <原因>`，退出码 1；成功打印 `OK <文档>` 与汇总。
- 新增覆盖目录时把路径加入命令；不要用通配符或忽略参数绕过检查。

## 七、反例（本项目真实事故）

- **固定文件名 AGENT.md 被废弃**：文档名与目录名脱节，迁移成本高 → 一律 `<目录名>.md`。
- **索引过期**：旧 `context/AGENT.md` 只登记 4 个文件（实有 13 个），旧 `expression/AGENT.md` 记录了不存在的 `expression_classifier.h` → 索引必须现场核对。
- **数字漂移**：旧文档写 111 TEST_CASE / 523 断言，实测 166 / 818 → 数字一律实测并标日期。
- **枚举漂移**：README 只列 3 种 `ExpressionKind_E`，源码实有 5 种 → 以源码为准。
- **时序误述**：`once` 的 action 源码注释称"解析时立即执行"，实际在 finalize 后由 Executor 按命令行顺序执行 → 时序以调用链为准。
- **索引漏构建文件**：漏 `xmake.lua`/`main.cpp` → 校验脚本会 FAIL，不要绕过。
- **相对链接层级错**：`../` 多一层或少一层 → 用脚本校验，不靠肉眼。

## 八、完成定义（DoD）

- [ ] 每个目标目录存在 `<目录名>.md`，无 `AGENT.md`。
- [ ] 头部两行 blockquote 齐全，五节顺序正确。
- [ ] 索引覆盖目录内全部非 md 文件，符号 grep 可命中。
- [ ] 所有相对链接可解析；所有数字标注核对日期。
- [ ] `check-docs.mjs` 退出码 0。
- [ ] 父目录文档与项目登记表已同步。
- [ ] 未改源码、未跑构建（除非任务要求）。
